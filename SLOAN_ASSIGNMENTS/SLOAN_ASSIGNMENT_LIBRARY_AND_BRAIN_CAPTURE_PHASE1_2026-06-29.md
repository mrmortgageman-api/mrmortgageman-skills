### Deliverable 2: GOOGLE_DRIVE_LIBRARY_ASSESSMENT_PLAN_CURRENT_2026-06-29

**Purpose:** Define how Sloan will inventory Drive and tag content.

**Contents:**

1. **Assessment Methodology**
   - How will you access/search Drive? (Search queries, folder traversal, etc.)
   - Will you work in phases? (If yes, what's the sequence?)
   - How will you capture findings? (Spreadsheet, Notion database, markdown table?)

2. **Metadata Fields Sloan Will Capture**
   - For each folder: Name, purpose, owner, last modified, status (active/stale/unclear)
   - For each file: Name, purpose, created date, modified date, size, status, tags
   - Example: What does "CURRENT" mean? What makes something "stale"? What's "orphaned"?

3. **Definitions: What Counts As What**
   - **Duplicate:** Same content, multiple locations? Multiple versions with unclear master? Both?
   - **Stale:** No modification > 90 days? Never used? Flagged as archive but untouched?
   - **Orphaned:** File with no folder purpose? File referencing deleted content? Both?
   - **CURRENT:** One active version marked explicitly? Or inferred from date?
   - **Archive Candidate:** Stale + orphaned? Or just stale? Define threshold.

4. **What Sloan Will Not Touch**
   - Will not move files until Scott approves migration plan
   - Will not delete any files
   - Will not rename anything
   - Will not restructure folders
   - Will not modify file contents
   - Will document observations only

5. **Output Artifacts Planned**
   - What will the final Library Health Report contain?
   - Will you produce recommendations for new architecture?
   - Will you flag specific governance conflicts?

**Format:** Operational document (prose + checklist)

### Deliverable 3: SLOAN_WEEKLY_OPERATING_LOOP_CURRENT_2026-06-29

**Purpose:** Define recurring procedures Sloan will follow for Brain Capture, Library Assessment, and Newsletter Pre-Production.

**Contents:**

1. **Daily Capture Routine (5-10 min)**
   - What triggers Brain Capture? (Chat completion? Scott decision? End of day?)
   - What's the sequence? (Read chat → Identify decisions → Tag categories → Record in Notion?)
   - What's the template/format?
   - Escalation rule: When does something need Claude review before filing?

2. **Weekly Library Health Review (30-45 min)**
   - What gets reviewed? (New Drive additions? Naming violations? Duplicates? Stale items?)
   - How is it documented? (Report? Database entry? Notion page?)
   - Escalation rule: When does a finding require Scott decision vs. Sloan recommendation?

3. **Weekly Newsletter Intelligence Packet (1-2 hours)**
   - What data does Sloan gather? (Market signals? Agent activity? Regulatory changes?)
   - What format does the packet take? (Markdown table? Notion database? Drive doc?)
   - When is it delivered? (Day/time each week?)
   - Handoff: Who receives it? (Claude for synthesis?)

4. **Escalation Rules to Claude**
   - What findings/questions go to Claude for governance check?
   - What goes directly to Scott?
   - What does Sloan decide autonomously?
   - Template: "If [condition], then [escalate to X]"

5. **Approval Gates with Scott**
   - When does Sloan need Scott approval? (Migration plan? Architecture changes? File deletions?)
   - What does "approval-ready recommendation" look like?
   - Turnaround time expectation?

6. **Operating Constraints**
   - Time allocation per domain (Brain Capture: X%, Library: Y%, Newsletter: Z%?)
   - Tools Sloan will use (Notion? Google Drive? Markdown in GitHub? All?)
   - Backup/archival of Sloan work products?

**Format:** Procedure document with decision trees
