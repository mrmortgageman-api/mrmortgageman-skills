## Core Definition

Applied Intelligence is the disciplined process of combining human judgment with multiple specialized forms of intelligence to improve the quality and speed of decisions.

---

## Enduring Principles

### 1. Multiple Perspectives Improve Decisions
No single intelligence source—human or artificial—sees the complete picture.

- Gather diverse perspectives (strategy, operations, design, validation, execution)
- Perspectives have different roles; they are not competing opinions
- Disagreement is valuable when governed; chaos is expensive

### 2. Governance Converts Opinions Into Decisions
Perspectives without authority create noise.

- Authority is clear and delegated
- One decision authority (Scott) prevents diffusion
- Governance is not delay; it is discipline
- Every decision identifies its authority

### 3. Institutional Memory Preserves Only Approved Decisions
Not every conversation becomes permanent record.

- Ideas are explored, debated, refined
- Only approved decisions are promoted to institutional memory
- Institutional memory records decisions, not debate
- Clean institutional memory allows future decisions to build on past decisions, not rediscover them

### 4. Decision Latency Matters as Much as Decision Quality
A perfect decision that arrives too late is worse than a good decision on time.

- Full governance applies only to decisions that merit it (Class A)
- Execution decisions should not wait for council approval (Class C)
- The right governance path depends on decision class
- Speed and quality are both required

### 5. Systems Survive Model Changes Only If They're Principle-Based
Today's AI tools will change.

- Build on enduring principles, not specific tools
- Execution mechanisms (Claude, Cowork, Notion) are replaceable
- Governance architecture is not
- When a tool changes, the principle remains; only the implementation changes

### 6. Accountability Requires Decision Authority
Collective decision-making without authority creates ambiguity.

- Every decision has a single authority
- Authority brings accountability
- Authority also requires good faith engagement with perspectives gathered before deciding
- Governance is not authority overriding intelligence; it is authority synthesizing intelligence

### 7. Institutional Memory Is Organizational Intelligence
An organization learns only when it can remember what it decided and why.

- Decisions without rationale cannot guide future work
- Rationale without decision creates endless debate
- Institutional memory enables better future decisions, not just documentation
- Clean records enable faster future decisions

### 8. Purpose: Improve Decision Quality, Preserve Accountability, Increase Throughput
The Applied Intelligence Operating System exists to improve decision quality, preserve accountability, and increase execution throughput over time.

- Every governance rule should serve this triple purpose
- Every protocol should be evaluated against this purpose
- Every runtime should support this purpose
- If a rule, protocol, or tool doesn't serve this purpose, it should be removed

## How These Principles Manifest

**In Product Review:**
- Multiple specialized intelligences (strategy, operations, design, validation)
- Single decision authority (Product Owner)
- Clean governance path that prevents rework
- Only approved recommendations go to institutional memory
- Future reviews don't rediscover the same issues

**In Execution:**
- Class A decisions follow full governance (high stakes, architectural impact)
- Class B decisions get targeted review (medium stakes, workflow impact)
- Class C decisions rest with execution authority (low stakes, local impact)
- Escalation rules move decisions up when they affect approved architecture

**In Institutional Memory:**
- Decisions are recorded with authority, rationale, and date
- Debate is not recorded (stays in conversation)
- Future decisions can cite approved decisions rather than rehash them
- Memory stays clean; search remains efficient

## On Improvement

These principles are intended to be enduring. They should change only when experience reveals a fundamental improvement to the operating system.

This is not perfection. This is learning that has been validated through deliberate practice.

If you discover a principle that should be added, removed, or refined—document it as a lesson learned, propose the change, and let it improve the operating system.

The system improves because we pay attention to how it actually works.
